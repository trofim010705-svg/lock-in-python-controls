# Pump–Probe Lab: Signal Recovery 7230 + Newport ESP301

Готовое приложение на **PyQt5 + pyqtgraph + pyserial** с двумя вкладками.
Первая содержит существующий интерфейс локина, вторая — линию задержки,
сканирование, четыре графика и запись данных.

Руководство в загрузке относится к **ESP301** (в сообщении модель названа EPS301).
В `pp.zip` находятся проект и бинарные VIs LabVIEW; приложение реализовано
по заданной спецификации и ASCII-командам приборов. Бинарные VIs не исполняются
и не требуются для запуска.

## Запуск

Из каталога репозитория:

```bash
python -m pip install -r requirements.txt
python app.py --demo
```

`--demo` подключает симуляторы обоих приборов. Нажмите «Старт», чтобы получить
демонстрационные кривые. **Это математически сгенерированные данные**, а не
физическая модель конкретного образца. Режим указан в заголовке окна, сведениях
о приборах, заголовке `.dat` и файле комментариев.

Для работы с оборудованием:

```bash
python app.py
# При необходимости:
python app.py --serial 14078415 --timeout 2000
```

Нужен Python 3.9+, установленный VISA-драйвер, с которым работает ваш локин,
и USB-драйвер ESP301, создающий COM-порт. Приложение не устанавливает системные
драйверы. Прежний отдельный интерфейс продолжает запускаться:

```bash
python gui_app.py
```

## Порядок работы

1. Во вкладке **«Управление Lock-in»** подключите 7230. Выберите **Dual reference**,
   источники опоры обоих каналов, чувствительности, TC и остальные настройки.
   Дождитесь подтверждения фактических значений справа от полей.
2. Во вкладке **«Pump-Probe и Линия задержки»** выберите COM-порт и ось 1–3.
   Для прямого USB ESP301 руководство задаёт **921600 baud, 8N1**. Скорость
   выбирается отдельно для подключения через RS232-адаптер.
3. Нажмите «Подключить». Приложение читает версию, модель оси, единицы, позицию,
   состояние двигателя, программные пределы SL/SR и историю ошибок.
   Подключение само по себе не включает двигатель и не двигает ось.
4. Ось должна быть заранее правильно настроена и откалибрована в **миллиметрах**.
   Проверяется `SN=2`. SN является меткой единиц, а не автоматическим переводом
   масштаба: приложение не меняет SN, разрешение энкодера, скорость, ускорение,
   пределы или режим поиска Home.
5. При необходимости нажмите **Home**. Это поиск по команде `OR` с ранее
   настроенным режимом `OM`, а не команда перехода к координате 0. Для движения
   приложение включает двигатель через `MO`, если он был выключен. Ошибки
   контроллера перед этим проверяются.
6. Задайте старт, стоп, положительный шаг, задержку после остановки, допуск позиции,
   тайм-аут движения, путь `.dat`/`.txt` и комментарии. Прямые и обратные сканы
   поддерживаются. Конечная точка включается всегда; последний шаг может быть
   короче заданного. При старте=стоп выполняется одно измерение.
7. Нажмите **Старт**. Все точки проверяются по прочитанным SL/SR до движения.
   Приложение не расширяет программные пределы автоматически.

«Задержка, ms» — выдержка **после подтверждённой остановки** в каждой точке.
Выберите её с учётом временных постоянных локина и механического установления.
Приложение не считает, что новая конфигурация фильтра мгновенно стабилизировала
физический сигнал.

Допуск проверяется по реальной позиции `TP`. При выходе за допуск, превышении
тайм-аута или ошибке прибора скан останавливается. По умолчанию он также
останавливается при перегрузке или потере захвата локина; невалидная точка не
записывается. Если снять соответствующий флажок, численные результаты сохраняются,
а ST/OV и номер подозрительной точки фиксируются в комментариях.

## Пауза, остановка, сброс и закрытие

- **Пауза** при движении отправляет `ST` и ждёт остановки. При продолжении та же
  точка достигается заново, выдержка повторяется. Если USB-считывание уже начато,
  завершается запись этой точки и скан встаёт на паузу перед следующей.
- **Стоп** останавливает выбранную ось и завершает файл с уже сохранёнными точками.
  Поздний USB-ответ на незавершённую точку после Stop отбрасывается.
- **Сброс** останавливает текущий скан и очищает графики. Файлы не удаляются,
  ось не возвращается к старту и не выполняет Home.
- При **закрытии окна** сначала завершаются движение, запись и сеанс измерений,
  затем закрываются COM/VISA и оба QThread. Принудительного `terminate()` нет.

`ST` — программная остановка с настроенным торможением, не аппаратный E-stop.
При физическом обрыве COM-кабеля приложение не может гарантировать доставку
остановки; это явно отображается как неподтверждённая остановка.

## Формат файлов

Файл создаётся **до первого движения**. После каждой завершённой точки строка
записывается и сбрасывается из Python-буфера. При завершении выполняется `fsync`.
Существующие файлы не перезаписываются: при совпадении имени добавляется `_001`,
`_002` и т. д. Пара файла данных и комментариев выбирается вместе.

`experiment.dat` или `experiment.txt`:

```text
# Position_mm    X1    Y1    X2    Y2
# Signal unit: V
# Simulation: False
0.000000000    1.23e-6    4.56e-7    -2.34e-6    5.67e-7
0.010000000    1.24e-6    4.55e-7    -2.30e-6    5.66e-7
```

Разделитель — табуляция, десятичный знак — точка. Сигналы записываются в **V**
или **A** в зависимости от IMODE; графики используют SI-префиксы.
Позиция — фактическая координата оси в mm, измеренная после выдержки.

Рядом сохраняется `experiment.comments.txt` с вашим комментарием, UTC-временем,
параметрами скана, идентификацией оси, настройками локина, методом чтения,
событиями ST/OV, числом записанных точек и итогом `complete`, `stopped`, `reset`,
`closed` или `error`. Для анализа удобно:

```python
import numpy as np
position, x1, y1, x2, y2 = np.loadtxt('experiment.dat', unpack=True)
```

Файлы внутри `data/` исключены из Git, чтобы результаты экспериментов не попадали
в публичный репозиторий вместе с исходным кодом.

## Скорость и синхронизация

**Один USB-владелец:** используется тот же поток VISA, что и в исходном интерфейсе
локина. Перед сканом завершаются ожидающие правки и запросы. На время измерений
настройки и фоновый опрос локина приостанавливаются; вкладка показывает причину.
Эксперимент не создаёт второе USB-подключение и не читает тот же endpoint из
другого потока. После завершения управление и фоновый опрос возобновляются.

**Один поток ESP301 и диска:** асинхронная машина состояний:

```text
PA → ожидание MD? → проверка TP и ошибок → выдержка QTimer
   → снимок локина → запись/flush → следующая точка
```

Ожидание движения проверяется каждые 10 ms; положение во время движения
обновляется примерно 10 раз/с. Чтение COM ограничено тайм-аутом 250 ms на ответ.
Циклов `sleep()` в реальном сканировании нет. GUI получает только короткие
сигналы о состоянии, позиции и готовой строке.

**Согласованное чтение четырёх сигналов:** документированная команда 7230 `?`
возвращает одновременный набор, заданный `CBD`. Для X1, Y1, X2, Y2 маска равна
`393219` (биты 0, 1, 17, 18). Если `M` показывает пустой неактивный буфер, его
определение и LEN временно сохраняются, задаётся эта маска, а после скана
восстанавливаются исходные CBD/LEN. Проверочный снимок выполняется до движения.

Если в буфере уже есть данные, идёт сбор кривой или быстрая команда не поддержана,
используются `XY1.` и `XY2.` без изменения буфера. Эти пары считываются
последовательно: **строгая одновременность всех четырёх чисел в таком fallback
не заявляется**. Выбранный метод `snapshot`/`paired` виден в журнале и комментариях.
При потере USB восстановление CBD/LEN может быть невозможно; это сообщается,
а исходные значения доступны в метаданных `original_curve_config` файла комментариев.

Графики обновляются отдельно, максимум 20 кадров/с. Все точки сохраняются;
прореживание pyqtgraph используется только для отрисовки. В памяти заранее
выделяется массив NumPy. Предельный размер одного скана — 500000 точек.
Реальная скорость ограничена движением, выдержкой, VISA и диском, а не частотой
перерисовки.

Настройки другого ПО, передней панели и удалённого Ethernet-клиента во время
скана не контролируются: для воспроизводимости прибором должен управлять один
экспериментальный сеанс.

## Команды ESP301 из руководства

| Команды | Назначение | Напечатанная страница |
| --- | --- | --- |
| `VE?` | Версия ESP301 | 3-147 |
| `1ID?`, `1SN?` | Модель/серийный номер и единицы оси | 3-83, 3-130 |
| `1SL?`, `1SR?` | Чтение программных пределов | 3-128, 3-131 |
| `1MO?`, `1MO` | Состояние/включение двигателя перед движением | 3-96 |
| `1PA<mm>` | Абсолютное перемещение | 3-106 |
| `1MD?` | Завершено ли движение | 3-94 |
| `1TP` | Фактическая позиция; по PDF без `?` | 3-138 |
| `1OR` | Home в ранее настроенном режиме | 3-104 |
| `1ST` | Остановка выбранной оси | 3-133 |
| `TB?` | Код, время и описание ошибки | 3-135 |

Префикс `1` заменяется выбранной осью 1–3. Команды заканчиваются CR,
ответы контроллера — CRLF (§3.4). Ошибки читаются через TB, без повторного чтения
того же события через TE, поскольку очередь ошибок очищается при чтении.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Проверки охватывают исходный интерфейс локина, ASCII-протокол и CR/CRLF ESP301,
единицы и пределы оси, ошибки/тайм-ауты COM, точки прямого/обратного скана,
потоковую запись и комментарии, неперезапись файлов, согласованные снимки и
fallback, восстановление CBD/LEN, четыре графика, поток USB, паузу в движении
и выдержке, Stop во время USB-чтения, сброс, обрыв обоих соединений,
ошибку пути до движения и закрытие обоих потоков.

Физические ESP301 и 7230 в этой среде не подключены. Результаты относятся к
документированному протоколу, подставному serial-устройству и полному demo-прогону.
На вашей установке сначала проверьте выбранную ось, Home, масштаб mm и пределы
перемещения, затем выполните короткий скан.
