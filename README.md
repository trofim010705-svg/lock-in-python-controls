# lock-in-python-controls
This is my attempt to transfer the web interface and control of the lock-in amplifier to python. I use the codex.

## Приложение PyQt5 для Signal Recovery 7230

`gui_app.py` переносит органы управления из четырёх приложенных HTML-страниц.
Архив RAR содержит CSS и изображения; они не требуются для запуска PyQt5.
Исходный `lockin_7230_usb.py` включён без изменений. Рабочий `main.py` служил
образцом формата USB-обмена; приложение его не импортирует.

### Установка и запуск

Нужен Python 3.9 или новее. Выполняйте команды из каталога проекта:

```bash
python -m pip install -r requirements.txt
python gui_app.py --demo
python gui_app.py
```

Для реального прибора используйте установленный VISA-драйвер, с которым работал
ваш `main.py` (например, NI-VISA), и ту же привязку USB RAW.
Одного пакета PyVISA недостаточно для доступа к оборудованию.
В режиме `--demo` VISA-драйвер не нужен. Это симулятор команд, а не физическая
модель измерений: показания в нём условные.

По умолчанию USB-адрес берётся из вашей библиотеки:
`USB0::0x0A2D::0x0027::14078415::RAW`.
Другой серийный номер можно передать без редактирования файлов:

```bash
python gui_app.py --serial 14078415 --timeout 3000
```

Стандартный предел генератора — 120 kHz. Только если прибор оснащён опцией
7230/99, используйте:

```bash
python gui_app.py --max-frequency 250000
```

Настройки записываются **автоматически**: выбор в списке — после выбора пункта,
число — по Enter, выходу из поля или изменению стрелками. Кнопок «Применить» нет.
Короткая задержка 180 ms объединяет быстрые повторные изменения; незавершённый
ввод числа не отправляется. Очередь USB выполняет записи последовательно и с
приоритетом перед очередным опросом. Start развёртки ждёт запись её параметров.

После записи значение перечитывается с прибора. Справа от поля видно:

- «Ожидает записи…» / «Запись / проверка…» — операция ещё не подтверждена;
- `✓ 10 ms`, `✓ 1 mV` — запрошенное значение совпало с фактическим;
- «Отклонено · 10 ms» — ошибка записи, показано фактическое значение;
- «Прибор: 20 ms» — прибор установил другое значение без ошибки команды;
- «Не подтверждено» — значение не удалось перечитать.

При отказе или изменении значения прибором редактор показывает фактическую
настройку. Новая правка, сделанная во время предыдущей записи, сохраняется и
пишется следующей. Вводимый текст и открытый список не затираются ответом USB.
Подсказка справа показывает запрошенное и фактическое значения; подробности
ошибок остаются в журнале. Знак `✓` подтверждает настройку, а не окончание
переходного процесса: после смены TC показаниям нужно время для установления.
При подключении приложение читает текущий режим; принудительных `REFMODE 2` и
`IE1 2`, как в вашем тестовом скрипте, нет.
«Перечитать вкладку» обновляет подтверждённые значения; незавершённый ввод и
новые правки сохраняются.
Для настроек другой вкладки чтение выполняется при первом открытии; после
изменения режима или автоматических операций данные инвалидируются.
Четыре показания доступны на всех вкладках. `Units` переключает SI / % FS;
для фаз используются градусы, для уравнений — целые числа прибора.
Блок измерений увеличен: напряжение и ток выводятся с SI-префиксами, например
`10 nV`, `2.5 µA`, а частота — `47.09228 kHz`.
Выбор показаний локален для приложения и не изменяет веб-настройку `DISP`.

### Состав вкладок

- **Main Controls:** вход A / −B / A−B / ток; AC gain, AC/DC, FET/Bipolar,
  Ground/Float, сетевые фильтры; Single reference / Dual harmonic / Dual reference;
  источник Demod2; источники опоры, гармоники, фазы и +90°; обе чувствительности,
  постоянные времени, крутизна фильтров, X/Y offsets, Auto Phase / Sen / Offset;
  Fast mode, synchronous, noise mode и noise buffer; генератор; virtual search
  и tracking; input limit и расчёт dynamic reserve по формуле HTML.
- **Oscillator:** частота и амплитуда; начальные/конечные значения развёрток,
  линейный/логарифмический шаг, время на шаг, Armed и Start/Stop;
  AM/FM с взаимным исключением, источником AM, глубиной, частотными и
  напряженческими центрами/диапазонами, управляющими фильтрами.
- **Rear Panel:** D0–D7 (направление, выходные биты, входные показания), числовые
  маски порта; ADC1–ADC4 и триггер; источники DAC1–DAC4 и пользовательские
  напряжения; RS232 (baud, bits, parity, echo, prompt, delimiter), Ref monitor,
  Expand. ADC и вход порта обновляются при активном опросе этой вкладки.
- **Equations:** два выражения `((A ± B) × C) / D`, переменные, C1/C2;
  консоль ASCII-команд с Command valid / Parameter valid и журналом ответов;
  Auto Default и Auto Measure. Формулы вычисляет сам прибор, Python `eval`
  не используется. FRQ/OSCF разрешены только в позиции множителя C, как в PDF.

### USB, потоки и ошибки

`USB7230` отвечает за соединение, кадры и бинарные статусы. `Instrument`
сопоставляет настройки с командами и проверяет ограничения. `Worker` запускает
все обращения к USB внутри одного `QThread`. `LockinWindow` и `Section`
содержат виджеты и представление состояния.

В приложенном модуле **нет класса**, поэтому используются его функции
`Connection_Open_USB()` и `Connection_Close()`. Импорт модуля и создание
`ResourceManager` происходят только в рабочем потоке.
`Inst_Query_Command_USB()` намеренно не используется: она читает бинарный
статус через текстовую строку и обрезает ответ фиксированной длиной.
Вместо неё применён рабочий способ из вашего `main.py`:
`write_raw(command + NUL)` / `read_raw()`. До декодирования ASCII отделяются
NUL и два бинарных байта; статус не маскируется, поэтому сохраняются флаги
перегрузки входа/выхода. Ответ обязательно читается и после команд записи.

При подключении приложение запрашивает `USBTERM`, принимает исходный формат
с/без статуса и устанавливает `USBTERM 1`. Дальше проверяется полный кадр.
Периодический опрос запускается одноразовым `QTimer` после завершения предыдущей
операции: циклы чтения не накапливаются в очереди. Пауза доступна от **10 ms**, по
умолчанию **100 ms**. Фактический период равен времени чтения плюс пауза и работа
очереди настроек. Под измерениями видны длительность USB-цикла и фактический
период последних обновлений. Уменьшение паузы не гарантирует 100 обновлений/с:
предел зависит от прибора, VISA и числа выбранных каналов. Для начала можно
попробовать 50–100 ms и посмотреть фактический период.

В одном цикле одинаковые запросы выполняются один раз; IMODE также читается один
раз. Полные ST/OV берутся из бинарных терминаторов всех ответов, включая ADC и
генератор, без дополнительных запросов ST/N. Новые правки допускаются во время
чтения и выполняются после текущей операции. Поля и списки не блокируются
во время USB-запросов; открытое меню остаётся открытым. Закрытие окна также
асинхронно ждёт освобождения USB и завершения потока, без `terminate()`.

Ошибки команды/параметра отображаются в журнале без потери соединения.
Тайм-аут, некорректный кадр или ошибка VISA закрывают соединение; для
продолжения нажмите «Подключиться». Автоматической повторной записи команд нет.
USB не обеспечивает транзакцию нескольких настроек: если ошибка возникла
посередине блока, уже выполненные команды перечисляются, блок перечитывается.
При потере связи актуальность всех показаний снимается.

### Красная индикация состояния

ST/OV расшифровываются текстом. Красный цвет означает перегрузку, отсутствие
захвата или ошибку команды, а не автоматически обрыв USB.

Для присланного скриншота `ST=0x31` означает: команда завершена (bit 0),
перегрузка выхода (bit 4), новые данные ADC (bit 5, не ошибка).
`OV=0x0C` = bit 2 + bit 3: **перегрузка X2 и Y2**, за пределами ±300% FS.
Показания второго демодулятора при этом могут быть недостоверными. Проверьте
его источник и уровень сигнала; выберите больший численный предел
чувствительности второго канала (например, 1 mV → 10 mV) и убедитесь, что флаг
исчез. Приложение не меняет чувствительность автоматически без действия
пользователя. Отдельные перегруженные измерительные каналы также выделяются.

В `main.py` были `VER`, `REFMODE`, `IE1`, `X1.`, `Y1.`, `FRQ1.`.
Ниже перечислены дополнительные команды, использованные приложением по PDF
`198004-a-mnl-d_removed.pdf` (номера относятся к напечатанным страницам).

| Вход | `IMODE`, `VMODE`, `ACGAIN`, `AUTOMATIC`, `DCCOUPLE`, `FET`, `FLOAT`, `LF`, `DEMOD2SRC` | 6.6.01; 6-7…6-10 |

| Чувствительность/фильтры | `SEN`, `TC`, `SLOPE`, `FASTMODE`, `SYNC`, `NOISEMODE`, `NNBUF`, `AS`, `AXO`, `XOF`, `YOF`, `EX` | 6.6.01, 6.6.03…04; 6-8…6-14 |

В двойных режимах используются предусмотренные §6.6.14 варианты:
`X1/2[.]`, `Y1/2[.]`, `MAG1/2[.]`, `PHA1/2.`, `REFP1/2.`, `REFN1/2`,
`SEN1/2`, `TC1/2`, `SLOPE1/2`, `XOF1/2`, `YOF1/2`, `AQN1/2`, `AS1/2`,
`AXO1/2`. В Single reference суффикс номера убирается.

Для частот и напряжений используются floating-point команды с точкой:
частота — Hz, амплитуда — V rms, время — секунды. `SEN` и `TC` принимают коды,
не сами значения. `XOF`/`YOF` используют сотые доли % FS. `RS` кодирует
чётность по PDF: bit1 включает parity, bit2 задаёт odd. В HTML кодирование
Even/Odd противоположное — здесь выбрана таблица руководства.

### Расхождения HTML и USB-руководства

Полное буквальное воспроизведение HTTP-интерфейса поверх только документированного
USB невозможно. Следующие различия явно отражены в GUI:

- **Bind to this computer's IP**: `IPLOCK`/`IPUNLOCK` по PDF работают при отправке
  через Ethernet. Элемент показан отключённым; приложение не выдаёт USB-вызов
  за успешную IP-привязку.
- **DIP switches, USB bus speed**: в приложенном PDF нет команд чтения этих
  сведений. GUI показывает причину недоступности. Статус подключения отражает
  реальное состояние VISA-сеанса; это не измерение скорости USB.
- **SYNC Auto (`SYNC 2`), `VRSEARCH`, `SOA`** есть в HTML, но не описаны в PDF.
  По умолчанию такие записи отключены. Флажок «Web-команды прошивки» разрешает
  их явно; поддержка по USB зависит от прошивки. Ошибка прибора выводится в UI.
- **Virtual reference** доступен без web-команд: задайте диапазон/положительный
  шаг/время в Oscillator и дождитесь подтверждения справа от полей. Search выполняет `VRLOCK 0`, `IE 0`,
  `FASTMODE 0`, `TC 8`, `FSTEP. <step> 2`, `SWEEP 1`. Это документированный
  linear seek, автоматически останавливающийся при превышении 50% FS.
  После успешного поиска нажмите tracking (`VRLOCK 1`). При включённых
  web-командах Search использует исходную `VRSEARCH` из HTML.
- `EX` и `SWEEP` в двойных режимах не поддерживаются таблицей §6.6.14:
  операции блокируются с объяснением. `IE` общий в Dual harmonic;
  `IE1`/`IE2` раздельны в Dual reference. Harmonic 2 в Dual reference равен 1.
- **Auto Default** отправляет `ADF 1`, сохраняющий параметры связи, поскольку
  HTML отправляет `ADF` без обязательного по PDF аргумента. Сброс происходит
  по нажатию кнопки. Приложение не выполняет его при запуске.
- Консоль предназначена для одиночных ASCII-ответов. Выгрузки буфера `DC`,
  `DCB`, `DCT` требуют отдельного протокола (§6.4.03) и в ней блокируются;
  изменения формата на `USBTERM 0` и полный сброс связи `ADF 0` также
  блокируются. Допускаются `USBTERM 1` и `ADF 1`.
- Частоты генератора и фазовые/амплитудные каналы читаются отдельными командами.
  Четыре числа на экране не заявляются как строго одновременный снимок.

### Проверка

```bash
python -m unittest discover -s tests -v
```

Тесты используют подставной транспорт и Qt offscreen. Проверяются бинарные
байты ≥128 и NUL, команды всех трёх reference modes, масштабы и ограничения,
offsets, частотная развёртка, AM/FM, формулы, чётность RS232, порядок записи
центра/диапазона, частично выполненный блок, открытие всех вкладок,
редактирование цифрового порта, выполнение USB в рабочем потоке,
неблокирующее закрытие при активной операции и восстановление после имитации
обрыва. Дополнительно проверяются автозапись после завершения ввода,
сохранение открытого списка во время опроса и подтверждения записи, правка
во время предыдущей записи, отказ/изменение значения прибором, приоритет
настроек перед опросом, SI-формат и расшифровка присланных ST/OV. Реальный 7230 в этой среде недоступен: физические измерения, конкретная
прошивка, драйвер и дополнительные web-команды требуют проверки на вашем приборе.
